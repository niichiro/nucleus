📍 Место в сети

    Всегда включён, подключён к домашнему роутеру по Ethernet (надёжнее) или Wi‑Fi.

    Имеет фиксированный IP (или обнаружение по mDNS nucleus.local).

    В будущем mesh-маршрутизаторы (ESP32-C6) будут видеть его как одного из участников сети и могут ретранслировать трафик в его сторону.

⚙️ Функциональные обязанности

    Zigbee-координатор (когда придёт стик).
    Он будет управлять Zigbee-сетью: разрешать устройствам присоединяться, хранить ключи шифрования, передавать команды и принимать телеметрию. Другие ESP32-C6 в роли Zigbee-роутеров расширят покрытие, но координатор — один (или резервный, но это позже).

    Хранитель полного CRDT-состояния дома.
    На диске Orange Pi лежит снапшот всего CRDT-документа (состояния всех ламп, штор, датчиков, сценариев). Он синхронизирует свой документ с любым подключившимся узлом (телефоном, ESP32), который приносит изменения. Это аналог «полной ноды» в распределённой системе.

    Мост между IP-сетью и mesh-тканью.
    Orange Pi всегда в домашней IP-сети. Когда вы с телефоном дома, приложение подключается напрямую к его HTTP/WebSocket API. Если же телефон общается с ESP32 через BLE, команда может пройти через mesh-узел, а затем через Wi‑Fi попасть на Orange Pi, который выполнит её в Zigbee-сети.

    Сервер истории и логов.
    На него пишутся rolling‑логи (сохраняются последние N дней). Через API можно запросить логи за период.

    Опционально: хост для веб-интерфейса (PWA).
    nucleusd будет отдавать статические файлы фронтенда (nucleus-app), чтобы телефон/ноутбук могли открыть панель управления просто через браузер по http://nucleus.local.

🧠 Почему это не «мозг» и не единая точка отказа?

    При отключении Orange Pi сеть продолжит работать: ESP32-C6 могут напрямую управлять Zigbee-устройствами (если настроены как координаторы), а телефон через BLE свяжется с ближайшим узлом и будет дёргать его локальное CRDT-состояние.

    При восстановлении Orange Pi все узлы синхронизируют накопившиеся изменения. Данные не теряются.
