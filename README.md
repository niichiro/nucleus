# 🏡 Nucleus

**Децентрализованная операционная система для умного дома без облака, интернета и единой точки отказа.**

Nucleus превращает ваш дом и участок в живую ячеистую сеть, где каждое устройство (телефон, ноутбук, микроконтроллер) является равноправным узлом.  
Мы не зависим от магистрального интернета, проприетарных облаков и центральных контроллеров. Вместо этого — радиоэфир, прямая связь и мгновенная реакция.

## 🧠 Философия

- **Интернет вещей без облака и подписки** — все данные остаются у вас.
- **Цифровой суверенитет** — только вы решаете, как работает ваш дом.
- **Связь без инфраструктуры** — система продолжает работать при отключении интернета, роутера или электричества.

## 🧱 Архитектура

Nucleus базируется на трёх типах узлов и трёх беспроводных технологиях, объединённых единым протоколом.

| Узел | Роль | Беспроводные интерфейсы |
|------|------|--------------------------|
| **Orange Pi 3** | Стационарный сервер, Zigbee‑координатор, хранитель логов и полного состояния | BLE (периферия), Zigbee (через USB‑стик) |
| **ESP32‑C6** | Полевой контроллер, ретранслятор mesh‑сети, локальный исполнитель | BLE, ESP‑NOW, Zigbee (опционально) |
| **Телефон / ноутбук** | Пользовательский интерфейс, мобильный узел сети | BLE (централ) |

### 📡 Связь между узлами

- **Телефон ↔ Orange Pi / ESP32** – BLE (короткие GATT‑соединения).
- **ESP32 ↔ ESP32** – **ESP‑NOW** (без подключений, низкая задержка).
- **Orange Pi ↔ ESP32** – BLE.
- **Orange Pi ↔ Zigbee‑устройства** – Zigbee (через координатор).

Таким образом, **BLE** служит универсальным клеем для всех типов устройств, а **ESP‑NOW** — скоростной магистралью между контроллерами.

## 💬 Протокол Nucleus

Все сообщения кодируются в компактный бинарный формат (postcard) и передаются поверх BLE / ESP‑NOW.

- **Announce / Heartbeat** – периодическое объявление о себе: идентификатор узла, тип, список подконтрольных устройств.
- **Command** – команда управления: `{device_id, action, ttl, timestamp}`.
- **Ack / Status** – подтверждение выполнения с новым состоянием.
- **Query / Response** – запрос и ответ о состоянии устройств (используется при синхронизации после возвращения в сеть).
- **Reboot / OTA** – перезагрузка и обновление прошивки по воздуху.
- **Log push / pull** – критичные события рассылаются немедленно, полные журналы запрашиваются по требованию.

## 🗺️ Дорожная карта

### Фаза 0 – «Виртуальный дом» (текущая)
- [x] Инициализация репозитория.
- [ ] Настройка BLE‑периферии на Orange Pi (приём команд от телефона).
- [ ] Эмуляция устройств через HTTP API / MQTT.
- [ ] Логирование (rolling‑логи) и mDNS‑обнаружение.

### Фаза 1 – «Железо оживает» (после прибытия Zigbee‑стика)
- [ ] Подключение Zigbee‑стика, запуск `zigbee2mqtt`.
- [ ] Реализация управления реальными Zigbee‑устройствами через BLE‑команды.
- [ ] Синхронизация состояния на Orange Pi (файловый снапшот).

### Фаза 2 – «Настоящая mesh‑сеть» (после прибытия ESP32‑C6)
- [ ] Прошивка `nucleus-node` с поддержкой ESP‑NOW и BLE.
- [ ] Лавинная маршрутизация (flooding) и кэширование ID сообщений.
- [ ] Связка «телефон → ESP32 → ESP‑NOW → … → Orange Pi → Zigbee‑устройство».

### Фаза 3 – «Полная автономия»
- [ ] Распределённые сценарии без участия Orange Pi.
- [ ] Автоматическое переключение BLE / ESP‑NOW при перемещении.
- [ ] Окончательная отделка интерфейса, OTA-обновления, документация.
