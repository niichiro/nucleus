# 🏡 Nucleus

**Децентрализованная операционная система для умного дома без облака, интернета и единой точки отказа.**

Nucleus превращает ваш дом и участок в живую ячеистую сеть, где каждое устройство (телефон, ноутбук, микроконтроллер) является равноправным узлом.  
Мы не зависим от магистрального интернета, проприетарных облаков и центральных контроллеров. Вместо этого — радиоэфир, прямая связь и мгновенная реакция.

## 🧠 Философия

- **Интернет вещей без облака и подписки** — все данные остаются у вас.
- **Цифровой суверенитет** — только вы решаете, как работает ваш дом.
- **Связь без инфраструктуры** — система продолжает работать при отключении интернета, роутера или электричества.
- **White-box, а не конструктор** — узлы питаются от обычных USB-блоков, ни одного дата-кабеля; телефон — основной интерфейс; узлы и устройства обнаруживаются сами (BLE-реклама, mDNS).

## 🧱 Архитектура

Nucleus базируется на трёх типах узлов и трёх беспроводных технологиях, объединённых единым протоколом.

| Узел | Роль | Беспроводные интерфейсы |
|------|------|--------------------------|
| **Домашний ПК (сервер)** | Сервер: Zigbee-координатор (USB-стик), хранитель логов и полного состояния, мониторинг | BLE (централ), Zigbee (через USB-стик) |
| **ESP32-C3** | Полевой контроллер, ретранслятор mesh-сети, BLE-периферия, локальный исполнитель | BLE, ESP-NOW |
| **Телефон** | Пользовательский интерфейс, мобильный узел сети | BLE (централ) |

### 📡 Связь между узлами

- **Телефон / ПК ↔ ESP32** – BLE (короткие GATT‑соединения; телефон и ПК — централы, узлы ESP32 — периферии).
- **ESP32 ↔ ESP32** – **ESP‑NOW** (без подключений, низкая задержка).
- **ПК ↔ Zigbee‑устройства** – Zigbee (USB‑стик + zigbee2mqtt на сервере).

Таким образом, **BLE** служит универсальным клеем для всех типов устройств, а **ESP‑NOW** — скоростной магистралью между узлами. Zigbee живёт за стиком на сервере и узлам не нужен.

Покрытие Zigbee-сети растёт от самих устройств: каждое розеточное (питаемое) Zigbee-устройство — уже роутер. Если в дальней комнате питаемых устройств нет, туда ставится опциональный узел на **ESP32-C6** (Zigbee-роутер + BLE-периферия); для остального достаточно C3.

## 💬 Протокол Nucleus

Все сообщения кодируются в компактный бинарный формат (postcard) и передаются поверх BLE / ESP‑NOW.

- **Announce / Heartbeat** – периодическое объявление о себе: идентификатор узла, тип, список подконтрольных устройств.
- **Command** – команда управления: `{device_id, action, ttl, timestamp}`.
- **Ack / Status** – подтверждение выполнения с новым состоянием.
- **Query / Response** – запрос и ответ о состоянии устройств (используется при синхронизации после возвращения в сеть).
- **Reboot / OTA** – перезагрузка и обновление прошивки по воздуху.
- **Log push / pull** – критичные события рассылаются немедленно, полные журналы запрашиваются по требованию.

## 🗺️ Дорожная карта

> ℹ️ Аппаратура: Zigbee-стик + 2× ESP32-C3 Super Mini (приехали по ошибке вместо C6 — этого достаточно; C6 — опция, докупается точечно при дырах Zigbee-покрытия).

### Фаза 0 – «Виртуальный дом» ✅
- [x] Инициализация репозитория.
- [x] Настройка BLE‑периферии на Orange Pi (приём команд от телефона).
- [x] Эмуляция устройств через HTTP API / MQTT.
- [x] Логирование (rolling‑логи) и mDNS‑обнаружение.

### Фаза 1 – «Железо оживает» (текущая)
- [ ] Подключение Zigbee‑стика, запуск `zigbee2mqtt` на сервере (ПК).
- [ ] Управление реальными Zigbee‑устройствами командами Nucleus (HTTP / MQTT / BLE).
- [ ] Синхронизация состояния на сервере (файловый снапшот).

### Фаза 2 – «Настоящая mesh‑сеть»
- [ ] Прошивка узлов ESP32‑C3 (`node/`) с поддержкой ESP‑NOW и BLE.
- [ ] Лавинная маршрутизация (flooding) и кэширование ID сообщений.
- [ ] Связка «телефон → ESP32 → ESP‑NOW → ESP32 → ПК (BLE‑централ) → Zigbee‑устройство».

### Фаза 3 – «Полная автономия»
- [ ] Распределённые сценарии без участия сервера.
- [ ] Опционально: узлы ESP32-C6 как Zigbee-роутеры и локальное управление Zigbee без сервера.
- [ ] Автоматическое переключение BLE / ESP‑NOW при перемещении.
- [ ] Окончательная отделка интерфейса, OTA-обновления, документация.

cd nucleus
# Сборка ядра
cargo build --release -p nucleusd
# Запуск сервера
